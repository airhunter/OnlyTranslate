# 识文标注口径 · 版本 1

只有用户确认的裁决属于标注。发布版输出是行为基线，不是默认正确答案。Agent 的评审报告和建议不自动转换为确认标注。

- `translate`：应翻。正文、公告、文档旁注和达标评论可纳入。
- `exclude`：不应翻。导航、账户操作、推广 CTA、独立推荐摘要和表单界面等排除。
- `either`：用户明确认可收录和排除两种行为，回归时均不报违反要求。
- `pending`：尚未裁决，不计为确认；可以撤回此前确认的要求，旧记录保留。

评论和其他阅读块使用同样的正文证据及用途标准；评论区域提供阅读上下文，但不降低证据要求。孤立的 “That worked for us.” 不达标；完整长评论里的短结尾可以随整条评论保留。

区外短文案需要明确阅读上下文。独立推荐摘要留给全页模式；长篇推广文案不会因字数长就成为正文。容器、标签和相邻块是判断证据，人工不必为了符合当前实现而认可它的输出。

标注绑定页面快照和原文块的位置。相同文字出现在不同位置时分别处理。仅目标容器、合并或分段变化，不等于原文减少。

标注修改填写理由并保留修订历史。产品口径整体变化时升级本文版本，列出并重新审核受影响的标注。第一版仅报告已确认要求是否违反，以及标注覆盖数量，不推断整页或整个网站的准确率。

## 已接受的已知限制与发布

内容裁决和是否接受带着已知问题发布是两种决定，不能互相替代。用户明确接受当前限制时，保留原 `translate`／`exclude` 及裁决历史，在 `accepted-issues.json` 追加确认记录。这不改变版本 1 对“该翻／不该翻”的定义，也不把失败改成 `either` 或 `pending`。

每条记录绑定页面、快照及 HTML 摘要、原文块及文字摘要、裁决 ID、口径版本和已接受的选中文本节点 ID。`reviewer` 为 user，必须有确认日期、原因、状态和 revision。只有与本次未满足结果完全匹配且状态为 accepted 的记录才不阻断发布。新裁决、不同的未满足覆盖、不同快照都不能沿用。若算法以后满足原要求，则正常计为满足，不再计为未满足的已知限制。

撤销接受时追加同 ID 的更高 revision，状态设为 revoked，保留之前记录。代理只能按用户明确指令登记真实接受或撤销；测试须使用隔离 corpus。缺快照、摘要错误、回放失败等完整性问题始终阻断，不受例外影响。
