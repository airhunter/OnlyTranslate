## 实现目标

先把 OnlyTranslate Full Page 的网页翻译能力与 Read Frog all 模式作明确对照，再修正已有缺口；随后实现维护者提出的网页结构自动选择。完整差异、源码链接与同页验证清单见 [Read Frog all 模式能力差异表](./readfrog-all-gap-analysis.md)。

全页目标是扩大网页文字的有效覆盖，同时保留合理的内容保护、站点兼容和用户选择的展示模式。它不要求每个自然语言字符串、每个控件和每个属性无条件翻译，也不把所有侧栏、作者或界面内容一概视为必须跳过。

已完成四组已有 HTML 的 all/full 双语实机对照，见 [同页结果、第一阶段清单与验收标准](../testing/fullpage-comparison-20261019.md)。它们是本地通用结构样本，未完成仅译文、真实网站 profile 和全部能力对照。维护者要求先确定目标与方案，本轮不修改功能、测试、依赖或配置；不包含打开网页后自动触发翻译。

后续已补 [真实博客和论坛的主页/正文配对对照](../testing/fullpage-real-comparison-20261019.md)，不再以本地样本代替网站观察。第一阶段除外围文案覆盖，还需解决主页卡片摘要“已有译文但被裁切不可见”的显示问题。早期报告中的超时、未测模式为当轮状态；当前范围与证据限制以下述收口报告为准。

当前结论与第一阶段清单见 [全页翻译模式对照与第一阶段方案](../testing/fullpage-mode-comparison-20261019.md)：博客/论坛 32 个组合已观察，Threads 仅有局部记录。维护者已确认 Chrome 中的 OnlyTranslate 是发布版，并要求停止实测；这些结果不等于当前分支缺陷验证或验收。仅译文使用双方支持的 Google（Read Frog 禁止微软仅译文），发布版观察到正文链接/主题入口离开显示树，因此安全写入优先于扩大收集范围。当前仅整理方案，不继续测试或改功能代码。

## 边界与有意保留的差异

脚本、样式、扩展自身 UI、译文、真实代码与公式继续保护。用户输入、草稿、密码、contenteditable 区域不因 full 扩大范围而纳入普通翻译。即使上游存在更宽松路径，也不降低这些保护。

站点声明不等于页面安全边界。Read Frog 不把 translate=no 当通用遍历禁令，对 html/body.notranslate 和嵌套 notranslate 的处理也不同。我们应在 full 上单独对齐这些路径，同时保证自身 UI、代码、编辑区不受影响；不能在共用 helper 中全局删除现有保护。

Read Frog 的属性白名单包括 input button/reset/submit 的 value，但属性 helper 能处理它，不等于普通页面一定会把独立控件送进该路径。显示文案与提交数据共用 value 的情况，必须先证明处理后提交语义仍正确。不能直接照抄该白名单作为默认写入权限。

OCR、Canvas 图中文字、视频音频及任意 closed Shadow DOM 不作为本次普通网页翻译的新增承诺。iframe、标签页标题则已经有 Read Frog 源码能力依据，属于已登记差距；未完成它们时，明确说明尚未对齐，而不是从比较中移除。

## 技术调整方向

### 范围与保护分开

在现有 collect、decision、dynamic、文本提取中统一传递实际模式。smart 继续聚焦阅读内容；full 仍做可见性、内容保护与站点兼容检查，但不把“非正文”作为统一否决理由。共享工具的默认行为保持原样，避免放宽划词、按键即时翻译等其他场景。

站点 profile 的 hard-skip 不能简单全部保留或全部忽略。以 Threads 为例，要核实哪些是只允许帖子正文的限制，哪些是避免重复文本或破坏交互的保护，再分别作用于 smart/full。现有 full fixture 的预期变化必须逐项有依据。

### 分组与显示遵循页面结构

复用已有正文分段、行内保护、direct-text run 与嵌套合并；第一阶段补按钮、链接、菜单项、表单静态文案、summary、表格等场景的分组。select/option 在本轮双语实测中两边均未出现译文，留待专门核实，不作为已确认的竞品覆盖缺口。分别验证独立小标签和带链接的完整句子，避免每个 span 发一个请求，也避免把多个菜单项串成一段。

双语与仅译文继续独立于翻译范围。双语补行内布局，保留原文；仅译文对稳定可对齐结构优先原位写入 Text 节点，沿用会话与源文本快照校验。现有整体 HTML 替换不得直接用于新纳入的交互控件。

真实主页卡片需区分“已生成译文”和“译文可见”。Lil’Log 首张摘要的译文被父容器裁切，Read Frog 截图也没有显示对应摘要译文。我们应以可用性为验收条件，对已翻译目标协调布局和恢复，不机械复制竞品显示问题，也不全局取消网站的截断与 overflow。

原位写入与属性写入需要保存原文、已应用译文及版本。目标被网站更新、断开或复用时，旧结果作废；恢复时仅回写扩展仍持有的当前值，不能覆盖网站新状态。不能为展示译文克隆按钮或重建其事件节点。

发布版实机观察到仅译文显示期间嵌套 a 离开显示树：Google 对照的文章从 58 个正文链接变为 0，恢复后回到 58；论坛 full 主题入口也出现点击不跳转。当前源码的备份/文本写入路径存在相应风险，但未验证安装包与当前提交一致。第一阶段先核查并处理当前路径，保留显示期间的原交互节点和 href，再放开新区域。不能把“可恢复”作为显示期间安全的替代证据。

### HTML 属性按实际路径处理

Read Frog 的双语主要走 plain 请求，仅译文走 html 请求。我们先以相同模式和服务类型核对，不承诺双语也能翻译所有不可见属性。对 HTML 路径中的属性保护补充可测试的映射与校验，明确保留 href、id、事件、状态和数据属性；不能把模型返回的任意属性直接回写页面。

独立 input 占位提示、纯属性图像、aria-only 控件和属性单独更新，先记录 Read Frog 实际请求与显示结果。确定是同等能力后再列为实现项；若属于我们主动新增能力，应明确标注为另一个扩展项。

### 动态与独立文档共享会话

初次扫描和动态扫描采用相同 full 策略。复用已有 mutation 合并、分片、取消、自身译文识别和队列，不通过忽略全部 UI 换取性能。剩余扫描任务须能继续调度，恢复或导航后停止，不以扫描预算耗尽冒充完成。

标题翻译和 iframe 分别维护可取消状态。frame 执行沿用浏览器支持的注入机制，不直接跨源读取父页面无法访问的 DOM；启动、恢复、设置切换和新 frame 加载必须有一致行为。权限不足、受限页面和失败情况单独记录。

| P2 HTML 片段属性 | 白名单属性保护、属性版本与恢复；验证条件属性覆盖 | 用相同服务、展示模式分开核对端到端能力，不擅自改提交值 |
| P3 独立能力缺口 | document.title、iframe 执行及状态协调 | 启动、换页、动态更新、取消与恢复有实机结果；记录权限限制 |
| P4 自动范围 | 自动/识文/全页选择、实际范围与原因、配置兼容 | 文章、信息流、分散页面、延迟加载与未知结构样本可解释地选择，且不反复切换 |

原先 P2 中控件文字的稳定写入、版本校验与恢复已纳入 P1，一起完成后再让新增交互区域对用户可用，不先发布只放宽过滤的版本。P2、P3 尚未完成时，只能说基础全页覆盖已改进，不能说 Read Frog all 能力已完整对齐。

第一阶段优先修本轮实测的导航/按钮、表单静态文案、表头/分类/翻页、summary/元信息缺口。body 外节点、translate=no/notranslate、text/plain 等源码差异先保留专项验证，不因本轮样本直接放宽。真实 Threads、Partner Center 等 profile 逐站补证，不从 localhost 结构结果推断真实站点行为。

真实网页采用同站主页/列表与正文/详情成对验收，补 R-AC1–R-AC6：真实域名、服务等待状态、卡片可见性、侧栏布局和虚拟化回收。Ziggit 实测说明 full 的站点 UI 排除也要核查，不能只放开通用标签后称完成。当前两个真实站点的双语观察不等于全部网站、全部展示模式验收。

## 自动范围的后续目标

此项是维护者提出的新增能力，不是从 Read Frog all 源码直接复制的行为。候选方案仍是“自动 / 识文 / 全页”，显式模式不被自动策略改变。

自动判断优先可信站点阅读结构，其次通用阅读证据；内容分散时选择 full。骨架屏、尚未挂载的正文、预算耗尽不能直接视为 full 的证据。探测阶段不包装 DOM、不插译文、不发翻译请求；使用独立、有界的结构抽样，不以已选中的正文作为覆盖比例分母。

范围在同一页面会话内保持稳定，导航后重新判断。具体评分、延迟策略、默认值与旧配置兼容、识文无结果时的处理，留到 P4 设计，当前不修改 smart 的 fallback 或默认配置。

## 验证与提交边界

完整样本清单见差异表。静态结构使用 `tests/fixtures/translation-target`，动态、写入、控件状态、恢复与取消使用代码测试；frame、布局和真实服务属性能力需实机验收。测试应记录纳入与排除原因，不能只对比是否出现译文。

功能实施时运行 `pnpm test:content`，新增交互与属性专项测试，并在阶段完成后执行 `pnpm verify` 和 Chrome 构建。修改主入口、消息或 frame 流程时扩大相关验证。设计文档只检查证据、链接、范围和 Git 差异，不重复运行全量代码测试。

本轮交付差异表、设计草案、同页报告及截图/快照，并更新 Roadmap。仅在 `codex/page-translation-redesign` 设计分支工作，不提交功能实现，不合并 main、不发布。
