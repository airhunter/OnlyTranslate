# 全页翻译模式对照与第一阶段方案

观察日期：2026-10-19 起；结论整理：2026-10-20  
状态：按维护者要求停止实测，基于已有记录收口；博客/论坛 32 个组合已观察，Threads 对照不完整  
代码状态：观察结束时仅有文档与证据；10 月 20 日先实施 P1-0，10 月 22 日继续实施第一阶段，最新状态见 [第一阶段实现与验收](./fullpage-phase1-20261022.md)。下文保留各次观察当时的状态与边界。

## 证据适用范围

维护者最后确认：Chrome 中的 OnlyTranslate 是**发布版本**，不是当前设计分支的本地构建；具体安装版本未独立核实。因此，下文 OnlyTranslate 实机结果均按发布版观察解读，不能认定当前 `d8569f3` 源码逐项存在同样问题，也不能作为当前分支验收。源码路径用于解释风险和安排修改顺序，不等于运行时归因已完成。

Read Frog 界面观察版本为 1.51.0，源码对照固定在 `fcb00beb21a9d674c0262346fbc422fbbf317c03`，同样未证明安装包与该提交逐字对应。博客/论坛覆盖比较可支撑产品方向；Threads 仅能列局部现象。当前不再补测、不切设置、不实现功能；下文验收均是未来获准实施后的标准。

后续授权更新：维护者已要求在独立分支先修仅译文交互。上述“不实现功能”是观察收口时的边界；当前只实施 P1-0，不重启竞品对照，也不将旧观察当作新构建验收。

## 已确认的结论

1. **Full Page 的覆盖不足是事实，但不是整个引擎失效。**两站的标题、文章、主题与回复已有翻译；主要差距在导航、侧栏、按钮、表头和元信息，且真实 profile 仍会影响 full。
2. **仅译文安全写入是第一阶段前置项。**同为 Google 服务，Read Frog 的文章仅译文保留 58 个正文链接；我们的识文和 Full Page 仅译文完成后均为 0，恢复后又回到原来的 58 个。论坛 Full Page 仅译文也把主题链接移入原文备份，点击译文标题没有跳转；恢复后原链接能进入帖子。
3. **生成译文不等于可见。**博客主页双语摘要已在 DOM 中生成，但被卡片裁切。竞品对应截图也没有显示摘要译文，不能算竞品独有优势；我们的目标仍应是让用户看到译文。
4. **识文不等于 Read Frog main。**Read Frog main 仍覆盖论坛表头、作者/时间、博客元信息和目录标题；我们的识文更窄。保留识文的阅读取向，不把这次工作扩展为重写识文范围。
5. **full 应保留识文已有的语义覆盖。**论坛识文会组合翻译一些分类标签，full 反而跳过其中部分。第一阶段不能只统计新增目标数，也要检查这种覆盖倒退。

以上是博客/论坛的发布版观察结论。网络恢复后已实际补完最后两项；Threads 另列有限记录，不能用论坛代替。**可以确定第一阶段的产品方向，但不能宣称已完成当前源码诊断，或已与 Read Frog all 全面对齐。**

## 三个决定方案的实机证据

### 仅译文链接：显示期间与恢复后必须分别验证

- `blog-article-rf-main-only-google-links.json`、`blog-article-rf-all-only-google-links.json`：原有 58 个链接均在，href 数组与原文一致。已翻译的引用仍处于链接节点内。
- `blog-article-ot-smart-only-google.json`、`blog-article-ot-full-only-google.json`：等待正文处理后，当前显示 DOM 中的正文链接为 0。原节点在 template 备份中，不在可操作的显示树。
- 恢复原文后读到 58 个链接，地址与基线一致。这证明原文能恢复，但不能证明翻译显示期间的交互合格。
- 论坛微软额外检查 `forum-home-ot-full-only-title-click.json`：点译文标题留在主页；恢复后点原链接进入同一帖子的 URL。Google 下也记录到 full 主题 href 缺失，不能把微软限制当作唯一原因。
- 主题链接本身作为识文目标时会保留；包含链接的父级成为 full 目标时，当前备份/文本写入方式会让锚节点离开显示树。源码 `usesSafeTranslationOnlyWrapper` 对 Google/微软均走该路径，与观察相符。

### 卡片摘要：可见性要按真实布局验收

双语首卡的容器底部约 y=568，译文文字起点约 y=733，父级仍 overflow:hidden，用户看不到译文。仅译文的文字起点回到容器内部。两种展示不能共用“DOM 出现中文”这个通过条件。竞品双语截图也未显示该摘要译文，本轮未对竞品作相同几何测量，不推断内部原因完全一致。

### 动态与完成状态：不能用一次节点计数判定

论坛会回收屏幕外帖子；滚动到同一条代码回复后再比较，两边已检查的代码文字保持原样。OnlyTranslate 文章仅译文的 MathML 数量和去空白文本多重集合保留，顺序可能随译文调整；这不等于任意公式布局、语义位置和事件身份已全部通过。

单次 loading 为 0 也可能落在后台批次之间。Google Full Page 文章首次记录仍有 17 个未处理链接，不能将其算作成功保留；等待后最终为 0、loading 为 0，恢复后为 58。保留的是完成后的证据文件，避免将过程态当结论。

## 第一阶段修改方案（当前仅实施 P1-0）

第一阶段交付目标：**普通 HTML 页面选 Full Page 后，阅读内容和普通界面文案有合理覆盖；双语译文实际可见，仅译文保留原交互，并能正确恢复。**不以重写识文、引擎或全面照搬竞品规则为目标。以下为完整清单，当前按维护者要求先实施 P1-0。

### 用户能看到的效果与边界

| 内容 | 第一阶段预期 |

“全页”是扩大可翻译网页文字的范围；不是一次请求翻完整个站点，也不翻译尚未加载的无限信息流。新内容加载或显示后继续处理，停止后不再写入。

### 实施顺序与失败处理

获准实施后，先对照当前分支中的对应收集与写入路径确定实际需改之处；发布版截图只作问题样本，不重复修复已经解决的问题。第一步完成链接/控件的安全显示与恢复，再扩大 full 范围，然后处理分组、布局及动态一致性。

正文带链接时不能简单按每个 Text 节点拆译而损失整句上下文；应复用行内结构保护，建立原节点与译文片段的可校验对应关系。保持原交互元素、地址和事件节点，不能把服务返回的任意 HTML 或属性直接回写。结构无法对应、服务失败或返回过期时，保留该目标原文，沿用失败/重试状态，不显示“成功”却隐藏入口。具体协议及涉及文件在实施设计时按现有能力选择，本轮不预定新依赖或新引擎。

译文到达时须确认会话仍有效、目标仍是同一份源内容；恢复只撤销扩展仍持有的修改，保留网站后来更新的文字和用户状态。卡片调整局限于必要目标并可还原，不能全局清除截断、固定高度或 overflow。

### 验收标准

1. **构建与主页/正文成对通过**：记录实际加载包的版本、构建来源与提交；两站四页分别跑双语和仅译文，每个区域记录已翻、保护、失败或有意差异。只完成文章不能代表主页通过；发布版旧截图不能冒充新实现验收。此项留到未来实施后执行，本轮不再测试。
2. **覆盖补齐**：已确认的导航、侧栏、按钮、排序表头、summary、元信息及静态表单文案有明确目标断言；full 不丢失 smart 已覆盖的分类文字。
3. **显示合格**：卡片译文位于实际可见范围；双语原文与译文均可读，只有译文模式不额外显示原文；常规和窄视窗检查遮挡、截断与可点击区域。
4. **交互保留**：正文 58 个 href、主题入口、按钮节点、输入 value/checked/选中状态不因翻译改变；代码测试核查原节点身份和事件仅触发一次，实机点击/键盘验证入口能用。当前实测仅证明部分 href/点击问题，不能冒充节点身份已通过。
5. **恢复与竞态**：恢复精确还原原文/布局，不覆盖网站后来更新的文字和输入状态；取消、导航、复用后迟到结果不能回写旧文案。
6. **动态回归**：目录/菜单先收起再展开，回复滚入、回收、再出现均不重复、不串目标；自己的译文不造成循环扫描。
7. **自动化与实机并行**：静态选区用对应域名 fixture；动态、插入、控件身份与恢复用代码测试。实施后跑 `pnpm test:content`、`pnpm verify` 并构建实际 Chrome 包；当前 207 个既有基线测试不能替代这些新验收。

#### 已实施的调整

1. 首选请求保留连续语句，在结构边界标记两侧加空格，避免标记紧贴短标签。只有有结构边界且首次响应无法应用的目标，才追加一次分行边界请求；不是每个段落都请求两遍，也不对 HTTP 429 等网络异常追加格式重试。
2. 真实 Google 响应显示，句首文字可以并入引用标签，普通强调片段也可能合并至相邻文字。原先要求每个非空 Text 都返回非空译文，会误拒绝这类结果。现在允许普通片段为空，但整个译文不可为空，原有每个链接/按钮的整体标签仍须非空。节点本身不删除，原始 Text 仍可逐项恢复。
3. 分隔标记及代码/公式占位标记仍必须各出现一次、顺序一致；未知标记、丢失、重复、重排及保护内容被改写，均不写入。格式重试复用首次原节点快照，恢复、取消或页面更新后不接受迟到结果。两次映射均失败则保留原文、显示错误/重试并清除无效缓存。
4. 分行格式只移除协议添加的一次换行，保留原文空白；连续格式保留服务返回的词间空格。LLM 结构请求增加标记和边界说明，普通与双语提示词保持原路径。

Google 的空片段、完整控件标签保护、格式重试、取消/源更新竞态和 429 不额外格式重试已加入代码回归。真实响应证明仍会有标记重排，不能为了消除失败提示而放松公式位置校验。
