# 本地识文评审台

## 启动与数据

```powershell
pnpm review:reading
```

浏览器打开 `http://127.0.0.1:4188`。只监听本机地址，不依赖云端服务或数据库。

默认数据目录为仓库同级的 `OnlyTranslate-review-data`。可在启动前设置 `ONLYTRANSLATE_REVIEW_DATA` 和 `ONLYTRANSLATE_REVIEW_PORT`；路径设置后应保持稳定，迁移时复制整个数据目录。默认 Chromium 来自本机 Playwright 缓存，其他位置可设置 `ONLYTRANSLATE_REVIEW_CHROMIUM` 为可执行文件路径。系统需要 Node、pnpm、npx、tar 和已经安装的 Playwright Chromium。

仓库记录 `tests/corpus/pages.json`、`release.json`、标注规范和 `decisions/<page>.json`。完整快照、资源、实翻截图和运行结果保存在数据目录。`output/reading-review-build` 是可重新生成的发布源码及采集器构建缓存，不参与类型检查和版本提交。

## 首批页面

首批包含 Teapaw 公告、Josh CSS 文章旁注、Lil’Log 首页、Ziggit 第六楼所在状态、Python 教程。可点击“补齐采集与实翻基线”，或进入单页依次点击“重新采集”“发布版实翻”“运行当前版”。补齐操作只处理缺少的记录，不重采已有快照。“回放当前版”在现有快照上批量运行识别，不访问翻译接口。任务串行运行并显示进度；重启后中断任务明确标记，可手动重试。

重新采集创建新的快照身份。旧快照、运行和标注保留，可通过“页面快照”选择历史状态。单页运行按钮绑定当前选择的快照。只在同一快照内选择对照运行，禁止把网站更新误算为算法差异。

每次采集使用独立 UUID，即使 HTML 相同也不复用旧目录。HTML、截图及元数据先写入 `.pending-*` 暂存目录，完整后再原子发布并更新 latest；失败目录不出现在可选快照中。原有 HTML 哈希形式的快照 ID 继续可读，不迁移旧基线、裁决或接受记录。共享资源按摘要只写一次，已有同名资源摘要不符时停止，不改写旧文件。

发布版锁定为 `tests/corpus/release.json` 中的公开发布 ZIP（位于 `.output`）、SHA-256、tag 和对应源码。工具核验包摘要与扩展运行时版本，从该 tag 的源码构建只读识别采集器，实际翻译由未修改的发布扩展执行。当前版采集器读取当前源码，不更改算法。

发布输入每次在新的 `output/reading-review-build/<tag>-verified-*` 目录准备：解压本次已校验字节的副本，并对锁定的完整 commit 执行 git archive；不凭旧 extension/source 目录存在就复用。运行元数据同时记录源码归档摘要。失败或旧目录不会用于后续重试，原有缓存及历史记录不删除。当前选择优先保证来源可核验，重复基线运行会重新解包。

第一版实翻采用 Microsoft、英文到简体中文、识文双语模式，独立浏览器配置，不读取个人浏览器凭据。实翻会把选中的公开网页文字发送给该服务。运行保存实际译文及全页截图；所有目标已处理或其原文已由其他已处理宿主完整覆盖、加载状态清空且无失败，并连续稳定后，才能作为完整基线。未插入译文的目标单独保留记录，不伪造译文。

完成统计按原文文本节点的位置 ID 核对，不能用重复文字或“没有剩余可定位文字”代替覆盖证明。无原文锚点且未处理的目标、部分覆盖、零目标仍不算完整。新运行分别保留直接处理数 attempted、覆盖目标数 coveredTargets、由其他宿主覆盖数 completedByCoveringHost，以及 completionRule 和判定代码摘要；历史运行不重新标记为完成。采集浏览器沿用 zh-CN locale，站点可能返回中文状态；遇到语言或采集范围限制，另存状态并记录原因，不为单个页面偷偷改变锁定的发布设置。

实翻观察结束后先保存实际目标、译文及进度，状态暂为 incomplete，再保存页面和全页截图。截图或HTML保存失败时仍保留运行数据，并在 artifacts 中记录失败，不能作为有效基线；进程中断也不会提前暴露 complete 状态。只有实翻与产物均完整才完成，不能仅看 translation.complete。

## 审核

### 整页目标确认

完整看过某个快照的识文目标后，可点击“确认整页目标”，不必先给每块文字打标签。总览显示“已人工确认”，支持筛选未确认和需复核页面。记录独立保存到 `tests/corpus/page-reviews/<页面ID>.json`，包含快照与输入摘要、规范版本、运行身份、选中原文位置、逐块裁决／接受记录上下文及操作历史，不批量制造逐块裁决或计算整页准确率。

重复运行或换提交后，同一快照的原文覆盖相同则继续保持已确认；容器合并、段落拆分或运行编号变化不要求重标。新增或减少目标时显示“需复核”，可筛选“整页确认后变化”，核对后点击“复核并确认整页”。左侧颜色仍相对发布版，右侧额外标明整页确认后的变化。

确认前先保存逐块草稿。未获接受的逐块违反、无法定位的目标、损坏的快照和失效的标注不能靠整页确认放行。已接受限制仍是未满足项，整页确认不代表已修复；逐块裁决、接受记录或规范更新后需重新确认。整页确认只针对目标选择，不替代译文质量或交互验收。

正式 build/zip 会重新采集并检查有效整页确认，包括无逐块标注的页面及历史快照。覆盖变化、上下文失效或完整性错误阻断构建，由用户复核，代理不能代批准。新快照不自动继承确认，旧快照要求继续保留；未确认新快照不计正确，也不删除旧要求。“撤销整页确认”追加历史，只撤销当前快照的整页要求，逐块裁决仍保留。UI/API 测试必须使用隔离临时 corpus。

点击样本进入单页评审。默认只展示固定的发布版基线和最新有效的测试结果，重复运行收进“历史记录”。每个快照首次使用时以当时最新的完整发布版实翻作为初始固定基线；以后重复实翻不会自动替换。展开历史可临时比较旧记录，收起或点击“恢复默认对比”回到日常比较。只有明确点击“设为固定基线”才更换默认对照，变更历史保存在该快照的 `comparison.json`，原运行和人工裁决均保留。

页面会高亮共同选中、新增、减少和疑似漏译；颜色不表示对错。右侧可筛选变化、疑似漏译、已确认或违反要求的块，并搜索全部原文。

点击清单或直接点击页面文字进行定位，连续选择“该翻 / 不该翻 / 都可以 / 待定”并填写备注，最后点击上方“统一保存本页”。选择和备注先作为浏览器草稿保留，切换文字、页面或快照不会丢失，刷新后也能恢复；草稿不计入正式标注。可筛选“待保存选择”集中复核。快捷键 1–4 选择，Ctrl+Enter 统一保存本页，j/k 切换清单。主动标漏译不依赖新旧算法是否产生候选。

统一保存后，裁决追加写入仓库内 `tests/corpus/decisions/<页面ID>.json`，保留历史；没有自动提交 Git。刷新、重启后仍存在，后续运行自动检查已确认要求。保存前的草稿只在当前浏览器 Local Storage 中，和已保存的正式文件分开。批量接口先校验整批，再进行一次原子写入；若有快照错配、无效块或其他窗口修改冲突，本批不写入、草稿保留。代理测试使用临时 corpus，不给真实页面作出用户裁决。

预览可切换适应面板的原文、原始视口、发布版实翻页面、原页整页截图和实翻整页截图。适应面板时响应式布局可能变化；原始视口和截图用于核对采集时的版式。预览禁用原站脚本、表单提交和外部导航，只加载已归档资源。目标比较使用冻结页面中原文文本节点的位置覆盖，完整原文单独保存；容器合并不自动算丢失，重复文字按位置区分。

采集与回放使用独立会话，普通网页 Service Worker 被阻止；回放响应必须包含对应快照身份。已发现的无效回放用独立的 `validation.json` 记录，原始输出保留，禁止作为有效基线或候选。运行时观察到的额外宿主单独记录，按原文覆盖合并，避免把列表父容器和子项重复计算为成绩。

## 第一版范围与限制

- 当前版默认只跑识别，不再次调用翻译接口；发布版已归档的译文用来核对实翻效果。
- 疑似漏译的具体条件是：采集时可见、两版均未选中、至少 80 个字符，并含中英文句号、问号或感叹号。它仅作长句提示，不判断推广用途，不等于完整漏译检测；短漏译和部分漏译可能不在此提示中。算法预算统计仍单独保留。
- 目前比较单位是原文文本节点；文本节点内部拆分、开放 Shadow DOM 和 iframe 的完整采集暂未覆盖，需要另存场景或 fixture。对覆盖无法定位的情况不能据此宣称完整无漏译。
- 首批支持手动固定某个关注元素后的状态；不执行原站动态脚本回放，动态行为仍用代码测试验证。
- 资源归档设有大小预算，遗漏数量会显示；未归档资源可能影响预览，原页截图为辅助证据。采集失败及访问验证页不计通过。
- 第一版尚不提供站点规则开关、批量退役判定、自动生成 fixture 或历史趋势；现有审计脚本的开关对照仍保留。退役规则需要补充专门对照后交用户确认。

## 开发验证

### 正式构建自动检查人工裁决

```powershell
pnpm test:reading
```

这个命令从 `tests/corpus/decisions/*.json` 自动发现要求，以每个快照、每个块的最新裁决为准。“待定”撤销之前的要求；“都可以”接受两种结果；未审核内容不算正确答案。只对有当前有效裁决的快照检查，包括已不在最新指针上的历史快照。一个段落只翻到部分原文也会违反“该翻”，选中任意部分原文就会违反“不该翻”。

每次检查重新构建当前源码采集器，在独立 Chromium 会话回放归档 DOM，不重新抓取线上网页，不调用翻译接口，也不读取旧候选结果充当本次成绩。原文索引、文字摘要、HTML 和资源摘要必须匹配；运行前后的源码、人工裁决和快照身份也会复核。有效回放作为新的候选运行保留，可以在评审台上查看。

所有正式构建使用根目录 `pnpm build`／`pnpm zip` 及其浏览器变体，由仓库级 `scripts/build-extension.mjs` 先执行同一检查，再调用 WXT。检查失败或工具缺失都不会启动 WXT；给正式入口指定 development mode 也不跳过。`zip:all` 和 release-it 继续经过这些入口。开发 `serve` 和热更新直接运行扩展，不启动评审工具。底层 `wxt build`／`wxt zip` 没有门禁，只用于扩展内部构建，不得作为正式交付入口或绕过失败的手段。`pnpm verify` 验证扩展和工具各自的类型与单元测试，不替代真实人工验证集检查。

报告保存在数据目录的 `checks/<检查ID>/report.json`，记录当前提交、源码摘要、采集器摘要、裁决集摘要、已检查快照、满足数、违反项及工具错误。终端也会逐条列出违反的原文和期望。这只是“已确认要求是否满足”，不代表未审核页面的准确率。

下列情况均以非零状态退出并阻止构建：要求未满足且未经用户明确接受、没有足够的确认、缺少本地数据、定位或规范版本失效、快照／资源损坏、回放失败、检查中途输入变化。策略在 `tests/corpus/check-policy.json`；至少保留一项确认，空数据不能算通过。不要为了构建通过而删裁决、降低标准或替用户作决定。

### 已接受的已知限制

用户可以明确决定“保留原裁决，但接受当前已知限制，不阻断发布”。这项决定单独记录在仓库内 `tests/corpus/accepted-issues.json`，不改原人工标注，不将其算作算法修复，也不自动推广至其他页面。

每条接受记录精确绑定页面、快照及 HTML 摘要、块和文字摘要、原裁决 ID／口径版本／方向，以及已接受的选中文本节点集合。用户确认日期、原因和 revision 必填。确认只允许对应的已知结果；重新保存裁决会产生新 ID，部分覆盖变化也需要重新确认。撤销需追加同 ID 更高 revision 的 revoked 记录，保留历史。

评审台和检查报告会同时显示“未满足”“已接受的已知限制”和“阻断项”。例如 13 项要求满足 11 项、未满足 2 项且已接受 2 项时，发布检查可以通过，但不能写成 13 项全部满足。选中对应块可查看用户接受原因。缺失数据、错误锚点、回放异常仍然失败；新出现的其他问题照常阻断。若以后算法修复了该项，则计入满足，不再计作未满足的已知限制。

接受清单也参与检查输入摘要。检查运行中如果接受决定被修改，本轮结果失效，必须重跑。

换机器或恢复数据时，需要同时恢复仓库里的清单／规范／裁决，以及外部数据目录中的相应 `snapshots/` 和 `assets/`。单有 JSON 裁决没有网页原文时会明确失败。构建不需要重新调用发布版翻译服务。

### 工具代码测试

```powershell
pnpm test:review
pnpm verify:review
pnpm test:content
pnpm verify
```

评审台代码、依赖声明、类型检查配置及单元测试统一位于 `tools/reading-review/`；扩展测试继续位于 `tests/`。浏览器采集适配器单向调用扩展真实识别代码，扩展入口和 WXT 配置不引用评审台。清单及人工数据仍在原位置，不因工程拆分而改变身份。详见 [工具工程说明](../../tools/reading-review/README.md)。历史审核报告中的旧路径保留当时记录，以本流程为当前入口。

新增网址通过“收录网页”登记，再采集、建立发布版基线并标出问题。实现修复后回放同一快照，新增和减少先交用户审核。共享识别改动运行完整可用 corpus；发布前记录覆盖范围和未审核项目。发布后新增运行记录，不覆盖旧答案。
