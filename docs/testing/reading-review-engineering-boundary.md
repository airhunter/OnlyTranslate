## 最终边界

| 部分 | 职责与依赖 |
| --- | --- |
| 扩展 `entrypoints/`、`wxt.config.ts` | 翻译、识别、扩展构建；不导入评审工具 |
| 工具 `tools/reading-review/` | 独立 pnpm 工作区，有自己的依赖、测试、类型配置、后端与 UI |
| 工具适配器 `adapters/onlytranslate.ts` | 单向调用扩展真实的识别函数；仍由工具单独打包，不进入扩展入口 |
| 仓库编排 `scripts/build-extension.mjs` | 先以子进程执行真实人工校验，成功后再以子进程调用 WXT |
| 人工数据与页面资料 | `tests/corpus/` 以及原外部数据目录保持原位置与身份 |

未拆成两个仓库，不引入第二套识别算法。现有评审 UI、采集、发布包校验、真实翻译和回放逻辑迁入工具工程，工具内路径根据自身模块定位；临时采集入口改写至输出目录。历史审核报告中的旧路径保留当时事实，以当前 README 和流程文档为准。

## 命令约定

- `pnpm compile` / `pnpm test`：扩展自己的类型与单元测试。
- `pnpm verify:review`：工具自己的类型与单元测试；测试数据始终隔离。
- `pnpm verify`：顺序检查两个工程，不冒充真实快照校验。
- `pnpm review:reading` / `pnpm test:reading`：保留原启动、真实人工校验便捷入口。
- `pnpm build` / `pnpm zip`、Edge / Firefox 变体：先校验再构建；`zip:all`、release-it 继续通过这些门禁入口。
- 开发服务继续直接使用 WXT，不加载工具；底层 `wxt build` / `wxt zip` 是无门禁的内部构建能力，不能作为正式交付入口或用于绕过失败。

门禁不存在跳过参数。工具缺失、校验异常、非零退出和信号退出均停止正式构建。已有整页确认、逐块裁决、已接受限制的判定与完整性检查原样保留。
